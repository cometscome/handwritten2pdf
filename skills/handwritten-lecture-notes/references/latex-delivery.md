# LaTeXのビルドと配布版

## 原稿と設定

既存の文書クラス、コンパイラ、マクロ、ファイル構成を先に確認し、使えるものを維持する。
新規の日本語教材には `assets/lecture-notes-ja.tex` を使える。LuaLaTeX、LuaTeX-ja、TikZ等が必要。
日本語以外では言語に合ったクラスとフォントに変更する。科目固有のマクロは対象原稿に追加する。

テンプレートには微分と接線の動作例がある。タイトル・対象・本文・図を講義に合わせて置き換える。
固定した教員名、所属、年度、単位系、章数を流用しない。
既存教材に表紙や装飾を追加するためだけに全体の組版を変えない。

一つの編集元から配布物を生成する。大規模なら主ファイルと `\input` する章・図に分けてよい。
機械生成した章別ファイルに手修正を加えると、次の生成で消えるため編集元を直す。

## ビルド

プロジェクト既存のビルド手順があればそれを使う。新規なら利用可能な `latexmk` とLuaLaTeXで依存関係を含めてビルドする。
以下は `notes.tex` を置いた作業ディレクトリでの例。

```sh
mkdir -p build
latexmk -lualatex -interaction=nonstopmode -halt-on-error -outdir=build notes.tex
```

`latexmk` がなければLuaLaTeXを複数回実行し、参照・目次が安定したことを確認する。
パッケージやコンパイラが不足する場合は具体的に報告し、無関係な環境設定を書き換えない。
キャッシュの書き込み先が必要なら、その講義の作業用ディレクトリに置く。

最終ログで次を調べる。

- コンパイルエラー、未定義の制御綴、数式モードの不整合。
- 未解決の式・図・文献参照、重複ラベル・PDFリンク先、再実行要求。
- 欠落文字・フォント警告、日本語の文字化け。
- `Overfull` のはみ出し、見た目に影響する `Underfull`、ヘッダ高や浮動体の警告。

警告を機械的に隠さず、該当ページの見た目と意味を確認して直す。
未解決参照や欠落文字を残して完成扱いにしない。

## 画像で確認

```sh
pdftoppm -r 140 -png build/notes.pdf build/page
```

式の改行、図と説明の距離、脚注、表、見出しの孤立、余白、ページ番号を確認する。
新規生成は全ページ、局所変更は変更箇所と再配置の影響範囲を見る。
大きな原稿ではページをまとめて見渡したうえで、数式・図・密な部分を読める倍率で個別確認する。
修正後は再ビルドし、最終版で確認する。テキスト抽出だけでは図の重なりは分からない。

## 章別版・結合版が必要な場合

依頼された場合に用意し、本文を独立に複製編集しない。

- 章の開始位置は明示的なファイル構成やマーカーで管理する。特定講義の章数・題名を固定しない。
- 各章の問題と解答が対応し、問題番号・式番号が配布方針と一致することを確認する。
- 他章への参照は「第3章の式(3.2)」など単独配布でも意味が分かる形にする。対応する参照の実在を確認する。
- 結合版で章ごとに番号をリセットする場合は、PDFリンク先や文献ラベルの重複を避ける。
- 生成一覧には、章題、編集元、生成PDF、必要ならページ数を記録する。
- 分割後に本文・図・脚注・参考文献・解答が抜けていないか、個別PDFを確認する。

既存の生成スクリプトを再利用する場合は、ハードコードされた年度・科目・章構成・マクロ・絶対パスを調べてから適用する。
正規表現で任意のLaTeXを安全に分割できるとは仮定しない。

## 納品

依頼されたPDFに加えて、編集可能なTeXと図のソースをまとめる。外部画像やデータを参照するなら、それらと出典も追跡できる形にする。
一時ファイル、検証用画像、ログを最終配布物と混ぜない。
最終報告では、内容検証・原本照合・組版確認をそれぞれ実施した範囲で記載する。
